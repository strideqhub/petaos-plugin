# 会员中心操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[会员中心](https://petaos.tech/member/dashboard)；或官网 Console → PETAOS Apps → 会员中心。

适用角色：会员运营、客服。

前置条件：有会员数据权限；确认目标会员及业务规则。

重要边界：会员等级/积分与 Loyalty 活动权益配置分别维护，不假定修改一处自动同步全部应用。积分、余额调整会影响客户权益。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-member-01"></a>

### member-01｜整理会员档案与人群

入口：[打开页面](https://petaos.tech/member/user)。

前置条件：已有会员账号或允许新增的模拟会员；准备标签/分组规则。

操作步骤：

1. 先在会员标签、会员分组维护业务分类。
2. 会员管理按会员标识查重，打开档案核对基本信息与归属。
3. 根据授权更新标签、分组或等级，保存后重新查询。

完成依据：目标会员显示正确标签、分组与等级，未影响其他会员。

异常/停止条件：不能用相同姓名作为唯一身份；手机号等个人信息仅在授权界面处理。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-member-02"></a>

### member-02｜配置签到并核对积分

入口：[打开页面](https://petaos.tech/member/signin/config)。

前置条件：确定签到奖励与积分调整权限；准备会员与日期范围。

操作步骤：

1. 在签到配置核对连续天数和对应奖励设置；变更前确认积分预算。
2. 在签到记录按会员和日期查看实际签到。
3. 在会员积分记录核对发生原因、增减值与余额；如需人工调整，单独确认对象、数量、原因。

完成依据：签到记录、积分流水与会员余额能够对应；配置保存不等于会员已签到。

异常/停止条件：发现重复奖励先保留流水证据，不通过删除记录修账。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

### Member Dashboard

入口：[/member/dashboard](https://petaos.tech/member/dashboard)。

前置条件：当前企业已开通此页，操作者拥有此次动作的数据与操作权限。准备目标编号或查询期间。

操作步骤：

1. 进入“Member Dashboard”，确认企业、可见数据范围和日期/状态等筛选条件。
2. 使用当前页提供的查询、刷新或标签，定位目标编号；打开可用详情核对业务来源与状态。
3. 如需导出，先确认数据权限、期间和筛选范围，再核对文件与页面口径。无记录或加载失败时报告该状态，不编造结果。

字段索引：本次未提取独立表单字段；按页面筛选/明细核对。

操作索引：Refresh

完成依据：“Member Dashboard”显示的目标数据与选定企业、筛选范围和来源记录一致；如导出，文件范围与页面一致。

证据：入口页面已查看；未提交本地页面模板已定位（不等于服务端链路已验证）。

### 会员配置

入口：[/member/config](https://petaos.tech/member/config)。

前置条件：当前企业已开通此页，操作者拥有此次动作的数据与操作权限。准备业务资料及所需关联记录；正式变更须在当前授权范围内。

操作步骤：

1. 进入“会员配置”，先查已有同名/同编号记录，确认当前状态与归属。
2. 选择实际可见的目标操作，核对下列相关字段及必填项；选择已有的关联对象，不凭名称猜编号。
3. 复核预览/详情：新增或编辑仅在用户已要求该变更时保存；审批、执行、发放、发送、删除、授权或启停不能当作保存后的自动下一步。
4. 保存或执行后重新查询同一编号。若动作影响库存、资金、权限或外部消息，必须再查相应流水、审计或投递结果；失败/超时先查结果再重试。

字段索引：hideId、Points Deduction、Max Points Deduction、Points Given per 1 Yuan

操作索引：Save

完成依据：“会员配置”的目标记录可重新查询且字段/状态符合此次操作；有外部影响时有独立业务证据，不仅是成功提示。

证据：菜单已核对；页面动作未实操本地页面模板已定位（不等于服务端链路已验证）。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
