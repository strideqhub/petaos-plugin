# 云会计操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[云会计](https://petaos.tech/finance/dashboard)；或官网 Console → PETAOS Apps → 云会计。

适用角色：财务人员、财务主管。

前置条件：具备对应财务权限；确认企业主体、会计期间、币种与批准的会计政策。

重要边界：本手册描述软件操作，不是税务或会计合规意见。过账、税务申报、重估和付款由有权人员复核；导出文件不等于已向税局申报。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-finance-01"></a>

### finance-01｜初始化财务主数据

入口：[打开页面](https://petaos.tech/finance/onboarding)。

前置条件：确认这是新账套还是已有账套，准备会计科目、联系人和商品信息。

操作步骤：

1. 进入初始化向导，先确认已有数据；已有账套不要重复初始化标准科目或加载示例数据。
2. 按向导核对会计科目；联系人填写类型、名称及必要税务资料。
3. 商品/服务核对 SKU、单位、单价和税类型；到税务中心由财务确认企业配置。
4. 返回总览检查主数据可查询；加载示例数据仅限明确的演练账套且单独确认。

完成依据：所需科目、联系人和商品可用于后续单据选择；已有正式账套未被覆盖。

异常/停止条件：科目/税务配置错误须先修主数据，不能在每張单据里临时凑数。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-finance-02"></a>

### finance-02｜从单据草稿到收款核对

入口：[打开页面](https://petaos.tech/finance/document)。

前置条件：有客户、商品/服务、开票日期和明细；获得该单据创建授权。

操作步骤：

1. 新增单据，选择业务类型、客户、开具与到期日期。
2. 添加明细，检查数量、单价、税和合计；保存并重新打开。
3. 依业务需要办理后续审核、分享或记录收款；每次外发/财务变更前复核对象和金额。
4. 在单据、银行/对账及相关凭证中按单号查看状态关联。

完成依据：草稿有单号且明细正确；如目标包含收款，须另有对应银行/收款证据，不能用发票代替。

异常/停止条件：相同业务参考号先查重；付款状态不明时不再次记收款。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-finance-03"></a>

### finance-03｜识别票据并形成费用草稿

入口：[打开页面](https://petaos.tech/finance/receipt)。

前置条件：有用户授权处理的票据，确认允许上传至当前系统及其识别服务。

操作步骤：

1. 上传经授权票据或选择手动录入；点击 AI 识别前确认可能发生模型费用。
2. 逐项校对供应商、开具日期、总金额、VAT 税额和费用分类。
3. 补充或修正明细，确认合计后生成草稿费用。
4. 进入费用页面打开新草稿，按原票据逐项核对。

完成依据：可追踪的费用草稿与原票据相符；AI 文本不是凭证真实性证明。

异常/停止条件：识别错误直接更正或手动录入，不按 AI 结果自动过账。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-finance-04"></a>

### finance-04｜银行对账与期间报表

入口：[打开页面](https://petaos.tech/finance/bank)。

前置条件：银行账户已配置，具备受限流水导入权限；会计期间已确认。

操作步骤：

1. 选择账户与期间，查已有流水，导入前核对文件范围和是否重复。
2. 按金额、日期、参考号定位流水并关联正确业务单据。
3. 在会计凭证查看对应分录及状态；到财务报表选择相同期间查询。
4. 导出前核对币种、期间、筛选和账套；预算/固定资产若报错则不继续推断数值。

完成依据：每条已对账流水有关联依据，报表与同口径明细可解释；导出范围清楚。

异常/停止条件：早期企业预算、固定资产页曾报服务器错误；2026-09-14 较新只读复核未复现，空表和导出禁用仍需测试数据核验，不能认定业务已通过。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
