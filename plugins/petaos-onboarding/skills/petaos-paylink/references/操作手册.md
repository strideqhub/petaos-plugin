# 收款 PayLink操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[收款 PayLink](https://petaos.tech/paylink/dashboard)；或官网 Console → PETAOS Apps → 收款 PayLink。

适用角色：收款人员、销售、财务。

前置条件：有 PayLink 权限；确定客户、币种、金额、到期日和业务参考号；支付通道/KYB 等上线条件按看板核对。

重要边界：创建链接、客户支付、交易核验、钱包结算和提现是不同阶段。水单图片不能单独证明真实到账。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-paylink-01"></a>

### paylink-01｜创建首个收款链接

入口：[打开页面](https://petaos.tech/paylink/ops/link)。

前置条件：确定是演练还是正式收款；准备唯一业务参考号与金额。

操作步骤：

1. 进入收款链接点击“新增”。
2. 填写必填标题和金额，选择客户；核对币种（当前页面默认 THB），按需填短码、业务参考号和到期日。
3. 补充描述，明确是否允许部分支付、可重复使用；不要未经讨论打开重复收款。
4. 复核后保存，回列表按标题/短码/客户查找，重新打开核对金额与行为。
5. 只有取得向指定客户发送的授权后，才复制并发送收款链接。

完成依据：链接在列表可查、金额币种正确并有短码/标识；这一步不要求也不证明款项到账。

异常/停止条件：保存后网络超时先搜索业务参考与标题，不连点创建。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-paylink-02"></a>

### paylink-02｜核验来款并解释结算

入口：[打开页面](https://petaos.tech/paylink/ops/transaction)。

前置条件：已有交易/水单和明确的业务单据；具备核验权限。

操作步骤：

1. 在交易记录按目标业务查找，核对付款金额、币种、时间、来源与状态。
2. 水单核验队列处理待核验材料；对照银行或通道可验证信息，不仅看图片。
3. 未知来款进入未知来款池，查证归属后才关联业务。
4. 结算对账核对已核验交易、手续费、准备金与结算周期；结算钱包核对可用/待结算金额。

完成依据：交易核验记录、业务关联及结算差异都有依据；收款链接状态与累计实收可解释。

异常/停止条件：未核验或未知来款不得当作已清分；提现由授权财务本人执行。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-paylink-03"></a>

### paylink-03｜开票、批量链接与投递追踪

入口：[打开页面](https://petaos.tech/paylink/docs/invoice)。

前置条件：已准备客户资料、票据明细；批量任务有目标名单与去重依据。

操作步骤：

1. 在客户页面查重并维护客户，再创建关联发票/收据。
2. 需要批量链接时先校对批量数据及金额，不把一次批量导入当作无风险操作。
3. 发送前预览收件范围与内容，单独确认外发；到投递记录查看每一条结果。
4. 通过追踪视图和客户跟进记录后续事项。

完成依据：每张票据、每个链接和投递对象可相互对应，失败项单独列出。

异常/停止条件：投递成功不代表客户已读或已付；重试前排除已经成功的对象。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
