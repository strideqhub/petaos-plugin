# 系统管理操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[系统管理](https://petaos.tech/system/my-tenant)；或官网 Console → PETAOS Apps → 系统管理。

适用角色：企业管理员、实施人员。

前置条件：确认企业与工作空间，具备对应管理权限；准备组织结构、岗位和经批准的角色清单。

重要边界：菜单可见不代表可授予权限。角色、令牌、三方授权、公开范围和套餐购买须单独确认；不在培训中填写真实密钥。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-system-01"></a>

### system-01｜建立组织与员工访问关系

入口：[打开页面](https://petaos.tech/system/dept)。

前置条件：已获组织配置授权；明确部门负责人、岗位和员工所属组织。

操作步骤：

1. 先查部门树，确认父部门后新增或编辑部门，不把组织名称重复建成同级部门。
2. 在岗位管理维护岗位，再到员工管理核对人员身份与部门归属；用户账号与员工业务档案分开核对。
3. 在用户管理查找账号，按批准清单配置其角色；需要扩大权限时由管理员确认后操作。
4. 让该用户重新进入工作空间，检查目标应用可见与数据范围。

完成依据：部门/岗位/员工记录可重新查询；目标用户只能看到被授权应用与数据，不能以管理员视图代验。

异常/停止条件：找不到人员先检查停用状态、企业范围和账号关联，不重复注册。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-system-02"></a>

### system-02｜查套餐与排查无权限

入口：[打开页面](https://petaos.tech/system/my-tenant)。

前置条件：有套餐查看权限；明确缺失的具体功能。

操作步骤：

1. 查看套餐与用量，记录当前状态、配额和到期信息。
2. 回到目标应用记录无权限或缺权益提示。
3. 管理员分别核对角色菜单授权与套餐权益；两者不是同一项设置。
4. 配额空白或服务器错误时停止续费推断，提交页面、时间和脱敏错误给支持人员。

完成依据：确认缺口属于角色、数据范围或权益；页面正常时能显示当前套餐用量。

异常/停止条件：早期观察曾出现服务器错误；2026-09-14 较新只读复核未复现，已显示套餐分类与用量。升级、续费仍未实测，不能宣称已通过。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-system-03"></a>

### system-03｜配置业务扩展字段

入口：[打开页面](https://petaos.tech/system/business-extension)。

前置条件：明确业务对象类型、稳定字段键、允许查看的角色和输出语言。

操作步骤：

1. 选择已有方案或新建方案，填写业务对象类型；如采购订单使用界面示例 erp.purchase-order。
2. 设置方案三语名称、Excel 文件名和工作表名；添加字段，配置字段键、类型、必填与三语名称。
3. 仅在数字公式类型中填写页面允许的安全算式；角色不选表示租户内全部角色可见，保存前必须复核。
4. 保存方案后，在“业务记录值”核对授权记录，再检查“报表与导出”的字段。

完成依据：重新打开方案配置仍在，授权角色可见且未授权角色不可见；公式用已知输入核对结果。

异常/停止条件：本次只查看方案编辑页，未保存、未证明所有业务对象已接入。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

### 用户管理

入口：[/system/user](https://petaos.tech/system/user)。

前置条件：当前企业已开通此页，操作者拥有此次动作的数据与操作权限。分配角色前必须已有经批准的非 `Super Administrator` 角色及其菜单/数据范围；若只能选择超管，停止并报告“缺最小权限角色”。准备业务资料及所需关联记录；正式变更须在当前授权范围内。

操作步骤：

1. 进入“用户管理”，先查已有同名/同编号记录，确认当前状态与归属。
2. 核对目标用户是否启用、是否属于当前租户、当前角色是否为空；从角色选择器读取真实可选项，不凭名称猜编号。
3. 角色分配是权限变更。展示拟分配的角色、菜单权限和数据范围，得到明确授权后才能保存；不得把 `Super Administrator` 当作普通员工培训角色。
4. 保存或执行后重新查询同一编号。若动作影响库存、资金、权限或外部消息，必须再查相应流水、审计或投递结果；失败/超时先查结果再重试。

字段索引：用户昵称、部门、用户名称、用户密码、手机号码、邮箱、用户性别、职位、角色、备注、新密码、确认密码

操作索引：新增、导入、导出、批量删除、编辑、更多、删除、重置密码、分配角色、取消、确认

完成依据：“用户管理”的目标记录可重新查询且字段/状态符合此次操作；用独立普通用户会话验证允许菜单/动作可用且越权动作被拒绝。只有超管页面或成功提示不算普通角色验收完成。

证据：菜单已核对；页面动作未实操本地页面模板已定位（不等于服务端链路已验证）。

### 角色管理

入口：[/system/role](https://petaos.tech/system/role)。

前置条件：当前企业已开通此页，操作者拥有此次动作的数据与操作权限。已有业务负责人批准的角色名称、职责、菜单范围和数据范围；没有批准清单时只盘点，不创建角色。

操作步骤：

1. 进入“角色管理”，先查已有同名/同编号记录；同时确认是否至少存在一个非 `Super Administrator` 角色。只有超管时记录阻塞，不自动复制或扩大超管。
2. 仅按批准清单创建或编辑角色，先配置最小菜单权限，再配置部门/本人等最小数据范围；不要先全选再回删。
3. 在保存前展示角色标识、状态、菜单权限和数据范围。创建、授权、启停或删除均需独立确认，培训讲解不能视为授权。
4. 保存后重新查询同一角色，并在用户管理中只给隔离测试用户分配该角色；用独立会话验证允许动作与至少一个拒绝用例。失败/超时先查角色和审计结果再重试。

字段索引：角色名称、Role Identifier、显示排序、状态、备注、菜单权限、Permission Scope、Department Scope

操作索引：新增、导出、批量删除、编辑、更多、菜单权限、数据权限、删除、取消、确认

完成依据：角色记录、菜单权限和数据范围可重新查询；隔离普通用户的独立会话只看到批准菜单，允许动作成功、越权动作被拒绝，并有审计记录。未做独立会话时状态只能写“角色配置完成、权限待验收”。

证据：菜单已核对；页面动作未实操本地页面模板已定位（不等于服务端链路已验证）。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
