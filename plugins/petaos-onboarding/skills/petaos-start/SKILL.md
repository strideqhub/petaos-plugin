# PETAOS 入门导航

## 入口

未注册客户从 [PETAOS 官网](https://petaos.tech/)、[产品](https://petaos.tech/products) 和 [解决方案](https://petaos.tech/solutions) 开始，不要求登录。已注册租户使用官网 → Console → 登录 → PETAOS Apps；已有授权会话时可用 [工作空间](https://petaos.tech/index)。优先复用当前目标网站标签页；客户指定其他合法部署时，以客户确认的域名为准，不把会话或凭证搬到另一个域名。

## 前置条件

- 阅读 [使用边界与验证状态](references/使用边界与验证状态.md)。这是一份技能/手册插件，不包含浏览器、账号或业务 API。
- 先判断客户属于“未注册了解/选型”还是“已注册租户培训/操作”。用户已经说明时不要重复询问；无法判断且会影响结果时，只问“您已经有 PETAOS 工作空间了吗？”
- 检查宿主当前可用的浏览器/电脑操作能力并遵循其使用说明。仅打开链接的能力不等于能读取页面或操作；不可虚构工具名、连接器或登录状态。
- 讲解不要求登录；实际操作需要用户已授权的企业、角色和环境。缺少会影响结果的信息时只问必要问题。用户已明确的目标不重复确认。

## 操作步骤

1. 未注册或处于选型阶段时读取 [Prospect discovery](references/prospect-discovery.md)。了解客户业务、当前流程和主要痛点，推荐一个最小业务旅程、对应模块、使用方法、提效机会、前置条件和演示下一步。只使用当前公开网站事实，不假装客户已有租户或功能已开通。
2. 已注册租户读取 [Registered tenant onboarding](references/tenant-onboarding.md)。从当前企业、角色、可见应用和目标任务生成能力清单及培训计划；不要按完整手册推断该租户权限。
3. 对租户请求再判断是“讲解”“陪练”还是“执行”。没有明确写入请求的培训默认只读；把计划操作及预期完成状态用一句话说清。
4. 用户要求打开网站且宿主可控浏览器可用时打开对应入口，读取最新 URL 和页面状态。需要登录、验证码或第三方授权时由用户完成，不索取或保存密码。未登录不假装已进入工作空间。
5. 按下表读取一个匹配的业务技能，再读取其中具体课程或页面操作卡；不要一次加载所有手册。跨应用任务按依赖顺序逐段推进，每段保留记录号与结果。
6. 使用现有菜单、表单和按钮，不新建替代业务页面，不绕过登录、审批、支付或权限机制。每个关键动作后重新读取状态，页面变化时先重新定位，不能重复点击旧坐标。
7. 培训逐步解释“为什么做、填什么、怎么判断完成”；只讲解或陪练时不保存业务。执行时只做授权范围内的动作；发布、提交、外发、付款等超出范围的后果先取得具体确认。
8. 按所选任务完成依据重新查询或打开记录。遇报错/超时先查是否已经成功，避免重复创建、支付或发消息；记录脱敏错误和时间，再报告阻塞，不自动开通服务。

### 首次创建流程

“请假/采购审批”进入 BPM；“让模型读取资料后生成内容”进入 AI。仅说“创建流程”且上下文无法判断时先问是哪一种。

BPM 的顺序：分类/表单/审批用户 → 保存模型 → 发布模板 → 发起申请 → 办理审批。按用户请求的阶段停止：只要求保存模型，不继续发布或提交申请。新建页只有保存入口，不承诺一键创建完整已审批实例。

## 完成依据

- 导航：实际到达的 URL、页面标题、企业/角色及目标入口；只给链接时写“已提供入口，未打开验证”。
- 未注册客户：给出场景摘要、建议的首个业务旅程、模块组合、使用流程、提效机会、前置条件、待确认项和公开下一步；不声称已进入或操作租户。
- 已注册租户：给出当前可用能力、角色化培训计划、已完成任务证据、未开通/报错项和下一批建议任务。
- 讲解：给出所选任务的入口、前置条件、操作步骤、完成依据和已知缺口；不声称已执行。
- 执行：给出记录编号、实际持久化字段/状态、必要的关联流水或审计，以及尚未完成项。成功提示不替代重新查询。
- 无可用浏览器：明确“仅人工引导”，列出用户应点击的页面和应回传的脱敏结果，不用脚本偷读浏览器缓存或调用未授权 API。
