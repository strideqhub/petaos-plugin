# 工作流程操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[工作流程](https://petaos.tech/bpm/manager/model)；或官网 Console → PETAOS Apps → 工作流程。

适用角色：流程管理员、申请人、审批人。

前置条件：已确认要创建“审批流程模板”还是“发起一笔申请”；准备分类、表单字段、发起范围和审批人。

重要边界：流程模型是模板，发布产生可用流程定义，发起后才有流程实例。保存≠发布≠审批完成。不要把 AI 工作流当作 BPM。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-bpm-01"></a>

### bpm-01｜准备流程分类、表单与审批用户

入口：[打开页面](https://petaos.tech/bpm/manager/form)。

前置条件：具备流程配置权限；已有可选部门和审批账号。

操作步骤：

1. 在流程分类维护分类；如使用用户分组，在用户分组选择已存在用户。
2. 在流程表单新建业务表单，例如“培训采购申请”，添加申请原因、采购金额和期望日期等业务字段，配置必填与类型。
3. 预览表单并检验空值、数字和日期输入；保存后重新打开确认字段。
4. 记录表单名称、分类和审批用户，供模型配置使用。

完成依据：表单可重新打开并显示预期控件，分类与审批账号在相应选择器可选。

异常/停止条件：业务表单类型和表单绑定方式以页面为准；找不到人员先检查组织与权限。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-bpm-02"></a>

### bpm-02｜创建并保存审批流程模型

入口：[打开页面](https://petaos.tech/bpm/manager/model)。

前置条件：已准备业务表单与明确的审批路径；只在指定演练空间使用模拟业务。

操作步骤：

1. 进入流程模型，点击“新建模型”，进入现有四步编辑页。
2. 基本信息：填写唯一流程标识、Process Name、分类、图标/描述；选择 BPMN 或 SIMPLE，设置可见性、发起范围和流程管理员。标识保存后不应依赖改名修复冲突。
3. 表单设计：绑定已保存的表单或选择系统提供的业务表单方式。
4. 流程设计：连接开始、审批节点与结束；每个任务命名并设置审批人规则。建议第一课只用单级审批，不先做复杂条件。
5. 更多设置：复核实际页面中的通知、权限及其他选项；检查所有步骤再点击“保存”。
6. 返回模型列表，按标识/名称查找并重新打开，核对设计与表单仍存在。

完成依据：模型记录和标识可查询、设计可重开；此时只证明保存成功，尚未发布或产生申请。

异常/停止条件：保存报某一步缺失则回到该步骤修正；已有相同标识先查询，不连续重试创建。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-bpm-03"></a>

### bpm-03｜发布流程模板并确认可发起

入口：[打开页面](https://petaos.tech/bpm/manager/model)。

前置条件：流程管理员已复核表单、审批人、路径、发起范围；获得发布具体模板的确认。

操作步骤：

1. 打开已保存模型的编辑页或列表中的发布入口；新建页只有保存，不应寻找不存在的自动发布按钮。
2. 核对版本、管理员、发起范围；旧版本已有实例时明确变更影响。
3. 确认后发布，按错误提示检查开始节点、任务名称、表单、审批人等。
4. 使用被授权申请人的身份进入“发起流程”，找到该模板并查看表单。

完成依据：发布成功且被授权申请人可选择该流程；记录模板标识和版本。

异常/停止条件：发布成功但不可发起时核对可见性、发起范围、停用状态及角色；不能扩大所有用户权限来绕过。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-bpm-04"></a>

### bpm-04｜发起申请、办理审批并验收

入口：[打开页面](https://petaos.tech/bpm/task/create)。

前置条件：模板已发布；申请人与审批人均有相应权限；有明确的测试数据和提交授权。

操作步骤：

1. 申请人在“发起流程”选择模板，填写业务字段，复核申请数据后提交。
2. 在“我的流程”找到新实例，记录实例号、当前节点和状态。
3. 指定审批人在“待办任务”打开该实例，核对申请及历史，填写意见后按业务事实通过或拒绝。
4. 申请人回到“我的流程”核对结果；审批人在“已办任务”核对办理记录；如配置抄送，在“抄送我的”核对。

完成依据：同一实例有发起记录、预期审批人、审批意见与终态；不能仅用提交成功提示作为完成依据。

异常/停止条件：无待办检查真实当前节点、审批规则和账号；超时先查询是否已生成实例，再决定是否重试。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
