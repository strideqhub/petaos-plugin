# MES 系统操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[MES 系统](https://petaos.tech/mes/dashboard)；或官网 Console → PETAOS Apps → MES 系统。

适用角色：生产计划员、车间、质检、设备人员。

前置条件：物料、单位、车间、工作站、工序、工艺与班组已维护；有生产或质检权限。

重要边界：工单、排产、领料、报工、质检和入库各有状态。报工数量不等于合格入库数量；真实设备/工厂动作不因界面保存而视作完成。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-mes-01"></a>

### mes-01｜配置产品工艺与质检基础

入口：[打开页面](https://petaos.tech/mes/pro/route)。

前置条件：有已批准工艺路线、产品与检验标准。

操作步骤：

1. 维护工序，新增工艺流程并填写编码、名称和说明。
2. Add Process 添加顺序，设置与下工序关系、关键工序、质检确认、准备/等待时间。
3. Associate Product 关联产品，检查生产数量/时间及用料关系；批准后 Confirm Enable。
4. 质检方案维护检测项、标准值、容差、方法和产品关联，缺陷字典先统一分类。

完成依据：启用工艺有正确顺序与产品关联，质检方案能找到对应产品及检测标准。

异常/停止条件：未确认工艺版本不创建生产任务；界面默认值不是技术标准。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-mes-02"></a>

### mes-02｜创建工单并排产

入口：[打开页面](https://petaos.tech/mes/pro/work-order/mps)。

前置条件：已有产品工艺、数量、需求日期、车间/工作站和班组产能。

操作步骤：

1. 生产工单新增 Work Order Code/Name，选择来源、类型、产品、数量、客户/供应商、批次与 Request Date。
2. 检查 BOM/用料明细，保存后按批准流程确认工单。
3. 生产排产选择工单，Add Task 设置工作站、排产数量、开始时间、工时和结束时间。
4. 在甘特图与排班日历核对资源冲突。

完成依据：工单可查询，任务关联正确工单/工序/工作站，计划数量和时间无明显冲突。

异常/停止条件：缺工艺、资源或数量校验失败时先修基础数据，不直接标记工单完成。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-mes-03"></a>

### mes-03｜领料、报工与成品入库

入口：[打开页面](https://petaos.tech/mes/pro/feedback)。

前置条件：有已安排的生产任务、领料单和实际生产结果。

操作步骤：

1. 在生产领料登记工单需要的实际物料；退料使用生产退料关联原业务。
2. 生产报工新增，选择工单、任务、工作站和产品，填写总数、合格、不良、各类报废及报工人/时间。
3. 检查数量关系及耗料/产出明细，先保存后 Submit，由有权人员 Approve 或 Reject。
4. 需要质检的结果完成质检后，在产品入库核对合格数量；库存现有量/流水与实际入库对应。

完成依据：报工有审核记录，数量解释清楚，合格入库与库存增量一致。

异常/停止条件：审批失败或重复报工先查工单/任务已有记录，不能用人工改库存掩盖。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-mes-04"></a>

### mes-04｜执行质检并做批次追溯

入口：[打开页面](https://petaos.tech/mes/qc/pending-inspect)。

前置条件：有待检对象、批次和适用质检方案；检验结果来自真实检验。

操作步骤：

1. 待检任务定位来源和检验类别，进入来料、过程、退料或出货检验对应页面。
2. 核对物料、批次、数量、方案和抽样要求，逐项记录实际测量与缺陷。
3. 按授权提交/审核判定，记录不合格处理，不由 AI 自动决定放行。
4. 批次追溯输入同一批次，核对物料、工单、检验与流转关系。

完成依据：检验数据、结论和处置有来源；追溯能连接实际业务记录。

异常/停止条件：缺方案/批次时停止判定；培训样本不得混入真实合格率。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-mes-05"></a>

### mes-05｜处理设备点检与安灯异常

入口：[打开页面](https://petaos.tech/mes/dv/check-record)。

前置条件：设备台账、点检保养项目与方案已维护；现场责任人明确。

操作步骤：

1. 点检记录按设备和日期填写实际检查结果，保养记录登记已执行项目。
2. 异常通过维修单描述故障、设备和责任人；车间异常可从安灯呼叫登记。
3. 执行人员处理后填写结果和时间，再核对状态、工作记录与相关生产影响。

完成依据：设备异常有处理人、过程和关闭依据；关闭不是仅把状态改成正常。

异常/停止条件：软件记录不能代替断电、维修或安全操作，现场动作交有资质人员。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
