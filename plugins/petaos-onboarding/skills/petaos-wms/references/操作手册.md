# WMS 系统操作手册

版本：2026-09-14 · 客户培训初版（非全链路认证）

插件版请先读 [使用边界与验证状态](../../petaos-start/references/使用边界与验证状态.md)。本文是编写时快照，历史观察不代表当前租户状态；实际操作以当前页面为准。

## 入口与适用范围

入口：[WMS 系统](https://petaos.tech/wms/dashboard)；或官网 Console → PETAOS Apps → WMS 系统。

适用角色：仓库管理员、收发货和盘点人员。

前置条件：仓库、商品/SKU、单位及往来企业已配置；明确业务来源单及实物数量。

重要边界：保存草稿不会等同库存完成；“完成入库/出库/移库/盘点”会影响库存。重复执行必须先查单号和流水。

本册复用当前网站，不创建第二套业务页面。未实际提交生产业务；下列完成依据是客户操作后的验收标准，不是本次测试已通过的声明。

## 培训任务

<a id="task-wms-01"></a>

### wms-01｜建立仓库与可用 SKU

入口：[打开页面](https://petaos.tech/wms/md/item)。

前置条件：明确仓库编码、商品分类、品牌和单位；有主数据维护权限。

操作步骤：

1. 先维护仓库、商品分类和品牌。
2. 商品管理新增物料编码/名称、分类、单位、品牌；用 Add SKU 建立实际规格和条码。
3. 往来企业维护供应商/客户类型，核对唯一编码。
4. 在入库的商品选择器查到目标 SKU。

完成依据：仓库、SKU 和往来企业可选择，规格与条码不冲突。

异常/停止条件：ERP 产品与 WMS SKU 是否映射需查实际记录，不能仅凭相同名称认定。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-wms-02"></a>

### wms-02｜完成一次入库

入口：[打开页面](https://petaos.tech/wms/receipt)。

前置条件：有实际收货和可用 SKU；来源业务单号明确，执行已授权。

操作步骤：

1. 新增入库单，选择 Receipt Type、仓库、Document Date、供应商与 Business Order No.。
2. 添加商品，填写实际 SKU 数量及页面要求的批次/货位信息；先保存草稿并重新打开核对。
3. 实物点收无误后，确认执行“完成入库”。
4. 在库存统计查该仓库/SKU，在库存流水按入库单号核对增量。

完成依据：入库单为完成状态，库存增加与流水数量一致；仅有草稿不算完成。

异常/停止条件：无法编辑已完成单据时按更正/退货流程处理，不删流水修库存。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-wms-03"></a>

### wms-03｜完成出库或移库

入口：[打开页面](https://petaos.tech/wms/shipment)。

前置条件：已核对库存、订单和目标地点；有实物执行授权。

操作步骤：

1. 出库管理新增出库单，选择类型、仓库、客户和来源业务号，添加 SKU 与数量。
2. 实物复核后执行 Complete Shipment，查出库状态和库存扣减流水。
3. 移库使用移库管理，明确 Source Warehouse、Target Warehouse、日期和 SKU 数量。
4. 执行 Complete Transfer 后，同时核对源仓减少和目标仓增加。

完成依据：同一执行单有完整状态与相应库存流水；移库两边数量平衡。

异常/停止条件：库存不足、已完成或已取消时先查状态，不再保存一个相同业务的新单绕过。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

<a id="task-wms-04"></a>

### wms-04｜盘点并解释差异

入口：[打开页面](https://petaos.tech/wms/check)。

前置条件：盘点仓库和时点确定，已协调盘点期间库存作业。

操作步骤：

1. 新建盘点单，选择仓库与日期；用 Import Warehouse Inventory 导入账面盘点范围。
2. Start Stock Check 后按实盘数量录入，逐项核对差异及备注。
3. 由负责人复核差异，确认后 Complete Stock Check。
4. 在库存统计与流水核对调整结果。

完成依据：盘点差异有实盘依据，完成状态及调整流水一致。

异常/停止条件：扫码工作台 Parse 可查单号/SKU/SN 等；多匹配应选择正确候选，不自动执行库存动作。

证据状态：结合现有页面、表单/源码编写；保存、发布、审批、支付、外发等业务后果均未在本次执行。

## 故障处理与培训验收

- 找不到入口：先核对当前企业、应用选择、角色和套餐；不通过猜 URL 绕过权限。
- 找不到记录：重置筛选并查编号、日期、状态、归属；不自动重复创建。
- 保存后超时：记录时间和业务编号，先查是否已创建/执行，确认结果后再重试。
- 按钮禁用：阅读状态限制；已完成/作废记录应走更正流程，不能删流水解决。
- 需要支持：提交脱敏页面路径、动作、时间、错误和业务编号后几位；不提交密码、Token 或个人档案。
- 培训验收：记录任务 ID、角色、环境、业务编号、操作前后状态、验证页、结果及未完成项。只把有业务证据的操作判为完成。
